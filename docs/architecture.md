# 架构说明

## 处理流程

```
图片目录
   │
   ▼
┌──────────────┐  MD5 批量哈希（线程池）
│  scanner.py  │──► md5_map: {md5: [paths]}
└──────────────┘
   │  每个 MD5 组取代表文件
   ▼
┌──────────────┐  pHash 批量计算（线程池）
│  hashing.py  │──► phash_map: {path: ImageHash}
└──────────────┘
   │
   ▼
┌──────────────┐  完全重复组（同 MD5 多文件）
│  grouper.py  │  相似组（两两相似度 > 阈值）
└──────────────┘
   │
   ▼
┌──────────────┐  保留策略链：像素面积 → 字节大小 → 字典序
│  selector.py │──► keep_map: {candidate: keep}
└──────────────┘
   │
   ▼
┌──────────────┐  操作计划（copy/move/keep）→ dry-run 预览 → execute
│ organizer.py │
└──────────────┘
   │
   ▼
┌──────────────┐  JSON + HTML 报告；webui.py 浏览器预览
│  reporter.py │
└──────────────┘
```

## 设计决策

1. **两阶段哈希**：MD5 先过滤完全重复（O(n)），只对代表文件做 pHash（O(m²) 比较，m ≪ n）。
2. **保留策略可组合**：策略是 `List[Path] -> Optional[Path]` 的函数；单个策略无法决定时返回 None 交给下一个策略。默认链：像素面积 → 字节大小 → 字典序。像素面积是"更大更清晰"的启发式，不是画质评分。
3. **默认只读**：CLI 默认生成报告不触碰文件；文件操作必须先显式传参（--move-* / --copy-*）并加 --execute。
4. **操作计划**：所有文件操作先记录成计划（action, source, dest），可预览可执行；每个操作独立捕获异常，一个失败不阻断后续，且失败时保护源文件。
5. **分组语义**：沿用私有项目的"每图至多一个相似组"策略，避免传递闭包把互不相似的端点归并（A≈B、B≈C、A≉C 时 A、C 不强行同组）。

## 模块依赖

```
scanner ← hashing ← grouper ← selector
                         ↓
                     organizer ← reporter ← cli
                                   ↓
                                  webui
```

依赖仅向下的方向，无环。

## 与私有项目的关系

本项目的算法基础（MD5 + pHash 两阶段）来自私有项目 `image-similarity-dedup`（2026-10-17 导入，Python 3.14 / PySide6）。私有项目是桌面 GUI；本公开项目是模块化 CLI + 报告 + 浏览器预览的跨平台工具。保留规则、文件操作安全机制、报告结构均为本项目的独立设计与实现。
